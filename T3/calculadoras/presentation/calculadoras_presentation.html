🧠 O que são Paradigmas de Programação?

Paradigma de Programação é um estilo fundamental de programação que fornece e determina a visão que o programador possui sobre a estruturação e execução do programa.

🔷 Paradigma Funcional

  • Baseado em funções matemáticas
  • Imutabilidade de dados
  • Ausência de efeitos colaterais
  • Avaliação de expressões
  • Recursão como estrutura de controle

🔶 Paradigma Lógico

  • Baseado em lógica de predicados
  • Declaração de fatos e regras
  • Resolução por unificação
  • Backtracking automático
  • Inferência lógica

🔷 Haskell - Paradigma Funcional

🎯 Tipagem Forte

Sistema de tipos avançado com inferência automática

🔄 Imutabilidade

Dados não podem ser modificados após criação

⚡ Lazy Evaluation

Avaliação preguiçosa - valores computados apenas quando necessários

🧮 Funções Puras

Sem efeitos colaterais, mesma entrada = mesma saída

Exemplo da estrutura de dados:
data Expr = Val Double | Add Expr Expr | Sub Expr Expr
eval :: Expr -> Maybe Double
eval (Add x y) = (+) <$> eval x <*> eval y

🔶 Prolog - Paradigma Lógico

📋 Fatos e Regras

Programa consiste em declarações lógicas

🔍 Unificação

Processo de matching entre termos

↩️ Backtracking

Busca automática por soluções alternativas

🎯 Declarativo

Você declara O QUE quer, não COMO fazer

Exemplo da implementação:
handle_input(Input) :-
    catch(Result is Input, _, write('Erro: expressão inválida')), !,
    write('Resultado> '), write(Result), nl,
    start.

⚖️ Comparação Técnica

Critério 🔷 Haskell 🔶 Prolog
Modelo de Execução Avaliação de expressões funcionais Resolução lógica por regras
Estrutura de Dados Tipos algébricos (ADT) Termos e átomos
Tratamento de Erros Maybe/Either (type-safe) Exception handling com catch
Parsing Parser combinators complexos Built-in com operador 'is'
Curva de Aprendizado Alta (conceitos matemáticos) Alta (pensamento lógico)

🛠️ Como Cada Uma Funciona

🔷 Calculadora Haskell

  • Parser: Analisa string em árvore sintática
  • AST: Representa expressão como estrutura de dados
  • Evaluator: Percorre árvore recursivamente
  • Safety: Maybe para tratar divisão por zero
  • REPL: Loop interativo no terminal
Exemplo: "2 + 3 * 4"
→ Add (Val 2) (Mul (Val 3) (Val 4))
→ eval → Just 14.0

🔶 Calculadora Prolog

  • Fatos: Definições básicas do sistema
  • Regras: Como processar entrada do usuário
  • Built-in 'is': Avaliação matemática nativa
  • Catch: Tratamento de erros
  • Recursão: Loop através de backtracking
Exemplo: "2 + 3 * 4"
→ Result is 2 + 3 * 4
→ Prolog avalia → Result = 14

⚡ Vantagens e Desvantagens

🔷 Haskell

✅ Vantagens:
  • Controle total sobre parsing e estrutura
  • Type safety elimina muitos bugs
  • Modularidade e reutilização de código
  • Expressividade matemática natural
❌ Desvantagens:
  • Curva de aprendizado íngreme
  • Mais código para funcionalidade básica
  • Complexidade do parser combinators

🔶 Prolog

✅ Vantagens:
  • Implementação extremamente concisa
  • Avaliação matemática built-in
  • Natural para problemas lógicos
  • Backtracking automático
❌ Desvantagens:
  • Menos controle sobre o processo
  • Debugging pode ser complexo
  • Limitado para alguns tipos de problemas

🎯 Demonstração de Uso

🔷 Executando Haskell

$ ./script_h.sh
$ ./calc

Digite uma expressão:
> 4 + 2 * (3 - 1)
Resultado: 8.0

> 10 / 0
Erro: divisão por zero!

> sair
👋 Encerrando a calculadora

🔶 Executando Prolog

$ swipl
?- [calculator].
?- start.

Digite uma expressão:
> 4 + 2 * (3 - 1).
Resultado> 8

> 10 / 0.
Erro: divisão por zero

> sair.
👋 Encerrando a calculadora

Observação: Note que o Prolog exige o ponto final (.) em cada entrada!

🎓 Conclusões

💡 O que aprendemos?

Diferentes paradigmas oferecem perspectivas únicas para resolver o mesmo problema

🔷 Funcional

Ideal para: Sistemas complexos, type safety, modularidade

🔶 Lógico

Ideal para: Problemas declarativos, inferência, prototipagem rápida
